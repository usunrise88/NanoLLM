{{if eq .Lang "ru"}}

  1. Установите NanoLLM и скачайте модель по умолчанию (её скачивает установщик или nanollm models pull).

  2. Запустите бенчмарк. По умолчанию — быстрый набор: auto и два репрезентативных пресета; полный — с --full:

    nanollm bench
nanollm bench --full

    Каждый пресет идёт в отдельном процессе: прогрев, три повтора, медиана и разброс. Пресет, который не помещается в память машины, отмечается как «не помещается» — это результат, а не ошибка. На время прогона закройте тяжёлые программы и подключите ноутбук к сети.

  3. После прогона NanoLLM покажет сводку и точный JSON, который уйдёт на сайт, и спросит согласие. Ничего не отправляется без вашего «y». Для скриптов — --submit.

  4. Без сети результат сохраняется в файл; отправить его позже:

    nanollm bench submit bench/results/bench-ДАТА-standard.json

  5. Удалить свою отправку (нужен тот же ключ установки, который её подписал):

    nanollm bench withdraw ID

    Режим «анонимно» (bench.anonymous: true) подписывает отправку одноразовым ключом: её нельзя будет удалить и связать с другими вашими отправками.

Что уходит на сайт

Метрики пресетов, версии NanoLLM и llama.cpp, хэши модели и профиль железа: процессор, память, видеокарта, производитель и модель компьютера, ОС, источник питания, тип диска. Не уходят имя компьютера и пользователя, серийные номера, UUID и MAC-адреса; тексты ответов модели — только их хэш. Подробности — в политике приватности.

Как считаются цифры

Для каждой группы (модель, набор, пресет, система, процессор, видеокарта, ОС) показана медиана и p25–p75. Каждая установка и каждая машина (грубый отпечаток железа) учитываются один раз, сколько бы раз они ни отправляли результат. Результаты разных версий набора не смешиваются. Скорость генерации проверяется на правдоподобие по пропускной способности памяти; выбросы уходят на модерацию.

{{else}}

  1. Install NanoLLM and get the default model (the installer fetches it, or nanollm models pull).

  2. Run the benchmark. The default is the quick set: auto and two representative presets; --full runs them all:

    nanollm bench
nanollm bench --full

    Each preset runs in a process of its own: a warm-up, three repetitions, the median and the spread. A preset that does not fit the machine is marked "refused" — that is a result, not an error. Close heavy programs and plug the laptop in while it runs.

  3. Afterwards NanoLLM shows a summary and the exact JSON it would send, and asks. Nothing is sent without your "y". For scripts: --submit.

  4. Offline, the result stays in a file; send it later:

    nanollm bench submit bench/results/bench-DATE-standard.json

  5. Withdraw a submission (with the installation key that signed it):

    nanollm bench withdraw ID

    Anonymous mode (bench.anonymous: true) signs with a throwaway key: the submission cannot be withdrawn or linked to your others.

What is sent

Preset metrics, the NanoLLM and llama.cpp versions, the model hashes and a hardware profile: CPU, memory, GPU, computer maker and model, OS, power source, disk type. Never host or user names, serial numbers, UUIDs or MAC addresses; of the model's answers, only a hash. See the privacy policy.

How the numbers are made

Each group (model, suite, preset, system, CPU, GPU, OS) shows the median and p25–p75. Each installation and each machine (a coarse hardware fingerprint) counts once however many times it submits. Results of different suite versions never mix. Generation speed is checked against memory bandwidth for plausibility; outliers go to moderation.
