# NanoLLM — публичный бенчмарк

NanoLLM прогоняет на железе пользователя пресеты работы на эталонных
промптах и замеряет скорость. Если пользователь согласен, результат уходит
на сайт вендора nano.llmto.day. Там на странице Benchmarks видно, как каждый
режим работает на каждом железе, вплоть до модели ноутбука.

В репозитории лежат и код бенчмарка (клиент в `nanollm`), и код сервиса
(`services/bench`). Сервис устроен так, чтобы его можно было вынести в
отдельный репозиторий без переделки; этот документ переезжает вместе с ним,
перевод на английский — при выносе.

Сроки по этапам — в разделе «По этапам» ниже и в [ROADMAP.md](ROADMAP.md);
задачи этапа 1 — пункт 1.11 в [STAGE1.md](STAGE1.md).

## Принципы

- **Явное согласие, без телеметрии.**
  - После прогона показываются сводка и точный JSON; отправка по `y` или
    кнопке.
  - `--submit` для неинтерактивного режима.
  - `bench.submit: ask|never`, `bench.submit_url`.
  - Без сети — `bench submit <file>` позже.
  - Текст согласия версионируется, `consent_version` уходит с отправкой.
- **Минимум данных.**
  - Только встроенные эталонные промпты, метрики и профиль железа.
  - Нет hostname, имени пользователя, серийных номеров и UUID, MAC.
  - Грубее, где можно: дата без времени, ядро major.minor, драйвер major.
  - Режим «анонимно»: одноразовый ключ, без возможности удаления.
- **Сравнимость.**
  - Версия набора закрепляет промпты (sha256), параметры генерации (greedy,
    seed, число токенов, ignore EOS), sha256 модели и драфтера, тег и
    коммит llama.cpp, версию NanoLLM.
  - Разные версии набора не смешиваются.
- **Честные цифры.**
  - Прогрев, 3 повтора, медиана и разброс.
  - Отдельный процесс на пресет: свои пики RSS, page cache и locked, свой
    лимит cgroup (`systemd-run --user --scope` или делегированная группа) или
    Job Object. Падение одного пресета не роняет прогон: `GGML_ABORT` и
    исключения C++ в libllama завершают процесс целиком.
  - Состояние машины записывается: сеть или батарея, профиль питания,
    загрузка до старта, свободная VRAM, enforcement strict или advisory.

## Наборы

- **`standard/v1`** (публичный).
  - **Пресеты.** Планировщик берёт помещающиеся. Пресеты с одинаковым планом
    (хэш плана) прогоняются один раз, результат засчитывается всем.
  - **По умолчанию `--quick`:** `auto` и два репрезентативных; полный
    набор — `--full`.
  - **Время.** Оценка длительности до старта; на целевом ноутбуке не больше
    15 минут (проверяется на этапе 3).
  - **Сценарии на пресет:**
    - загрузка;
    - `pp512`;
    - `tg128` с глубины 0 и `min(4096, n_ctx−256)`;
    - `chat-ru` через весь пайплайн: TTFT, decode, MTP вкл/выкл,
      acceptance, ускорение.
  - **Статусы:** `ok`, `skipped`, `refused`, `failed`. `skipped` и
    `refused` не считаются ошибками.
- **`dev`** (не отправляется): матрица §12 — контекст 1k/4k/16k × драфтер ×
  параметры O2. Результаты пишутся в `bench/results/<machine>/`. Формат
  общий.

## Формат `nanollm.bench/v1`

- **Заголовок:**
  - `schema`, `consent_version`;
  - `suite{id, version, prompts_sha256}`;
  - `client{nanollm, llama_cpp{tag, commit}, ggml_cpu_variant, os, arch}`;
  - `model{id, revision, sha256, drafter_sha256}`.
- **`machine`:**
  - `cpu{vendor, model, cores, threads, p/e, isa[]}`;
  - `memory{total, speed?}`;
  - `gpus[{name, vendor, vram, driver_major, power_limit_w?, cores?,
    unified}]`;
  - `system{vendor, family, product, form_factor, chassis}`;
  - `os{name, version, kernel_mm, wsl}`;
  - `power{source, profile}`;
  - `disk{type}`.
- **`runs[]`, на каждый пресет:**
  - `{preset, plan_hash, plan{mode, gpu_layers, n_ctx, slots, kv, fa,
    swa_full, mtp, threads, enforcement}}`;
  - `metrics{load_ms, pp_tok_s, tg_tok_s{d0, dN}, ttft_ms, chat_tok_s,
    mtp{acceptance, speedup}, peak_rss, peak_vram, peak_locked,
    peak_page_cache}`;
  - `reps`, `stddev`;
  - `output{sha256, tokens}`;
  - `status`, `reason`.
- **Подвал:** `date`, `duration_s`, `install_id`, `signature`.
- **Эволюция формата:**
  - JSON Schema из модуля `benchfmt` — контракт, проверяется в CI;
  - изменения v1 только добавляющие;
  - неизвестные поля сохраняются в сырых данных;
  - выведенный набор отвечает 410 или 426, клиент это обрабатывает.

## Профиль железа: `internal/hwinfo`, без cgo

- **Windows:**
  - SMBIOS через `GetSystemFirmwareTable('RSMB')`, без прав: типы 1, 3 и 17 —
    производитель, `SystemFamily`/`SystemVersion` (маркетинговое имя;
    `ProductName` часто SKU), шасси, скорость RAM;
  - `ProcessorNameString`;
  - `GetLogicalProcessorInformationEx` для P/E;
  - питание, режим питания;
  - драйвер видеоадаптера из реестра.
- **Linux:**
  - `/proc/cpuinfo`, топология и P/E;
  - DMI `sys_vendor`/`product_name`/`product_version`/`product_family`/
    `chassis_type` (без serial и uuid);
  - `power_supply`, `/sys/firmware/acpi/platform_profile`;
  - `rotational`;
  - NVIDIA: версия и power limit (`nvidia-smi -q -d POWER`, если есть).
- **WSL2:**
  - профиль хоста через interop `powershell.exe Get-CimInstance
    Win32_ComputerSystem`;
  - иначе ручной ввод `--system-model` (длина и набор символов ограничены,
    запись уходит на модерацию);
  - `wsl: true`.
- **macOS:**
  - `machdep.cpu.brand_string`, `hw.model`, `hw.memsize`, `hw.perflevel*`;
  - число ядер GPU (`ioreg`, `gpu-core-count`).
- **Везде:**
  - GPU из ggml;
  - CPU-вариант ggml и число потоков.
- **Тесты** на раннерах CI (там `form_factor: vm`); реальные ноутбуки — с
  этапа 3.

## Клиент

- **Команды:**
  - `nanollm bench [<model>] [--suite standard|dev] [--quick|--full]
    [--submit] [--out f]`;
  - `bench submit <file>`;
  - `bench withdraw <id>`;
  - внутренняя `bench worker`.
- **API для UI:** `POST /api/v1/bench` (admin) и
  `GET /api/v1/bench/{id}/events` (SSE).
- **Ключ установки.**
  - ed25519 в `<data_dir>/bench/identity.key` (права 0600).
  - **Подпись доказывает только владение:** удалить свою отправку и
    объединить повторы одной установки.
  - От подделки подпись не защищает. Новый ключ на каждый прогон обходит
    дедупликацию, поэтому агрегаты дополнительно считаются один раз на
    грубый отпечаток железа.

## Сервис `services/bench`

- **Модули.**
  - `benchfmt/` — отдельный модуль без зависимостей (`benchfmt/go.mod`,
    теги `benchfmt/v1.x.y`). Его используют и NanoLLM, и сервис.
  - Сервис — модуль `services/bench` с `replace ../../benchfmt`, пока живёт
    здесь. `go.work` не коммитится. CI идёт по каждому модулю отдельно.
  - После выноса (`git subtree split -P services/bench`) сервис зависит от
    тегированного `benchfmt`, а не от всего NanoLLM.
- **Структура:** `cmd/benchd`, `internal/{ingest,store,normalize,aggregate,web,admin}`,
  `migrations/` (встроенные нумерованные SQL, таблица `schema_version`,
  пересборка таблиц из-за ограничений ALTER в SQLite), `templates/`,
  `Dockerfile`, `deploy/` (compose + Caddy без IP в логах).
- **Хранилище:** SQLite (modernc, WAL).
  - **Сырые отправки неизменяемы** и служат источником истины.
  - Нормализованные таблицы и агрегаты пересобирает `benchd reindex` по
    версионированному нормализатору и таблице алиасов, а не правка руками.
  - Бэкапы с ограниченным сроком хранения: удалённая отправка исчезает и из
    них.
- **API:**
  - `POST /api/v1/submissions`: ≤ 256 KB, схема, подпись, правдоподобие;
    возвращает id и URL;
  - `DELETE /api/v1/submissions/{id}`, подписанный ключом;
  - `GET /api/v1/results?…` — медиана, p25/p75, число установок;
  - `GET /api/v1/facets`, `GET /api/v1/submissions/{id}`;
  - экспорт CSV/JSON под открытой лицензией данных (CC0 или CC-BY, решает
    владелец);
  - `/admin` по токену: скрыть или показать, алиасы, vendor-verified.
- **Страницы:** html/template и немного JS, RU/EN.
  - `/benchmarks` с фильтрами: модель, набор, класс устройства, CPU, GPU,
    модель ноутбука/ПК, ОС, пресет;
  - `/benchmarks/systems/<slug>`, `/benchmarks/cpu/<slug>`,
    `/benchmarks/gpu/<slug>`, `/benchmarks/s/<id>`;
  - «Как запустить», политика приватности;
  - сервис владеет `/benchmarks` за reverse proxy сайта; остальные страницы
    берут данные из JSON API.
- **Нормализация имён:**
  - CPU и GPU: убрать `(R)`, `(TM)`, частоту, «12th Gen»;
  - вендоры: `ASUSTeK COMPUTER INC.` → `ASUS`;
  - SKU → семейство через SMBIOS family;
  - Mac: `hw.model` + ядра GPU.
- **Доверие — сочетание мер:**
  - rate limit по IP в памяти (хэш с суточной солью, не хранится) и по
    ключу;
  - проверка схемы и диапазонов;
  - **потолок правдоподобия** только для tg без MTP: считается по
    размещению групп из плана (G1 и G6 исключены, смешанная выгрузка
    учитывает две пропускные способности) и таблице пропускной способности
    памяти. Если железо неизвестно — пометка «unknown» без отказа;
  - **хэш вывода — мягкий сигнал:** сравнивается длина совпадающего префикса
    внутри когорты (бэкенд + CPU-вариант ggml + repack + тег). Сам по себе
    причина отказа не является;
  - выбросы по MAD в когорте уходят на модерацию;
  - агрегаты считают каждую установку и каждый отпечаток железа один раз;
  - значок vendor-verified для машин владельца.
- **CI:**
  - workflow `bench-service.yml`: тесты, lint, образ, e2e (`benchd` + `bench
    --suite standard --submit` на фейке → результат виден на странице);
  - основной релиз сервис не включает.

## По этапам

| Этап | Бенчмарк |
| --- | --- |
| 1 | `benchfmt`, `hwinfo` (код и тесты на трёх ОС в CI), раннер с процессом на пресет, клиент, экран Bench на фейке. Сервис MVP после 1-C, e2e, образ. Staging, если есть хостинг. Черновики политики приватности и текста согласия |
| 2 (EPYC) | Первые настоящие прогоны: повторы, разброс, бюджет времени, CPU-потолки, strict через cgroup. Отправки vendor-verified класса «сервер» |
| 3 (ноутбук) | GPU-пресеты, SMBIOS и модель ноутбука на реальном Windows, WSL2 interop, power limit GPU, сеть/батарея. Экран Bench на реальном железе, ≤ 15 мин подтверждено. Первые публичные результаты |
| 4 | Mac (`hw.model`, ядра GPU, `uma-*`), Ryzen AI, Intel, i5-1035G. Публичный запуск страницы с релизом v1.0. NPU — с v2.0 |

## Риски

| Риск | Меры |
| --- | --- |
| Подделка или перекос результатов | Потолок правдоподобия, MAD в когорте, лимиты, модерация, vendor-verified. Подпись доказывает только владение |
| Персональные данные (GDPR, 152-ФЗ при российских пользователях или хостинге) | Минимум полей, согласие с версией, IP не хранятся, анонимный режим, удаление отправки, ограниченный срок хранения бэкапов |
| Несравнимые цифры | Версия набора, когорты, отдельный процесс на пресет, состояние машины в отправке |
